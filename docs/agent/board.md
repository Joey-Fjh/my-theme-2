  - **Round 1 settled (user, 2026-09-24): CSS and Liquid markup.**
    - How to write rules: state the logic and its reason, not an absolute ban. The lint catches the common ways to break the logic; a real exception (expected 1–2 per chain) carries an inline reason comment the lint accepts and is listed in the reference.
    - **Global settings chain (replaces scan #50, #91; extends to color).** Typography and color derive only from the chain `config/settings_schema.json` → `snippets/css-variables.liquid` → tokens → tier or scheme classes, so a change to the global settings reaches every consumer. Anything that bypasses the chain is a defect: Tailwind default typography or palette utilities, arbitrary values (`text-[14px]`, `bg-[#fff]`), CSS literals for typography or color properties, and custom variables not generated from settings. Enforcement: `@theme` resets the default typography and palette namespaces to `initial` (as breakpoints already are), and `lint:theme` checks Liquid classes and first-party CSS. Known exceptions: the two iOS zoom floors `max(16px, …)` in `sections/search.liquid` and `snippets/quantity-selector.liquid`; `transparent`, `currentColor`, `inherit`. Known violation to fix in the batch: `font-medium` in `sections/cart.liquid`. No hardcoded colors found in sources.
    - **Enforce by lint:** #51 `heading-h*` only on `h1`–`h6`; #52 no `body-*` on `h1`–`h6`; #47 no `@apply`/`@utility`/`@variant` in `{% stylesheet %}`; #48 no `<style>` in Liquid; #1 no executable inline `<script>` (data blocks allowed); #54 no raw `<svg>` in Liquid (use the `icons` snippet); #59 no bare `<img>` outside `image.liquid` (exception: `templates/gift_card.liquid`).
    - **#53 rewritten, not enforced:** two valid chains. Bridge a token into `@theme inline` only when markup needs an atomic utility (colors, spacing, z-index); tokens that form a recipe (typography tiers, motion) are consumed through a CSS-layer recipe class instead. Drop the motion-specific ban. Motion tokens have no consumer yet; they stay as frame capability.
  - **Round 2 settled (user, 2026-09-24): JS runtime.** Logic: each kind of side effect has one outlet, owned by a core module; components call the outlet. Lint targets bypasses:
    - #13 Alpine only in `alpine.adapter.js`; #14 `fetch(` / `XMLHttpRequest` only in `https.js`; #24 cart routes only in `cart.contract.js`; #16/#2 `document`/`window.addEventListener` only in core files (`base`, `events`, `https`, `utils`, `alpine.adapter`), components use `ThemeEvents` or Alpine `.window` modifiers; #17/#18 every `x-data` root carries `data-module-id`.
    - #27 no `x-transition` in Liquid: state motion uses CSS-layer recipe classes toggled by state (same chain as round 1); reset Tailwind `--ease-*` in `@theme`. Exceptions carry a reason comment.
    - Prose only: #15 (covered by #14), #22 and #20/#26 (approval gates, not chains), #23, #19. #3 is already enforced.
  - **Module loading checked against Shopify's official guidance (2026-09-24, Shopify Dev MCP):** import map, dynamic `import()`, visibility-lazy loading, no own `es-module-shims`, and Liquid-first rendering match [use import maps](https://shopify.dev/docs/storefronts/themes/best-practices/performance/use-import-maps-for-modules) and [load JavaScript on user interaction](https://shopify.dev/docs/storefronts/themes/best-practices/performance/load-javascript-on-user-interaction). Alpine (~16.5 KB gzip) is a deliberate trade-off against the "avoid frameworks" advice; do not add Web Components beside it. User decisions:
    - Add an import-map consistency lint: every `data-module-id` has an import-map entry and an `assets/` file, and every import-map entry has a consumer (a missing entry is a browser `TypeError`).
    - The cart layer (`cart.contract.js`, `https.js`, `alpine.store.cart.js`, ~6.2 KB gzip) stays static: derived themes keep cart drawer or redirect logic on every page.
    - Record in `javascript-runtime.md`, not code: when to preload a first-viewport module chain (`modulepreload` or preload on hover), and that below-the-fold components take `data-module-lazy`.
