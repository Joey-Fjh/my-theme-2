# Work Board

This board holds only what is not yet decided: the one active decision, evidence that has not become a plan, and deferred ideas. `docs/agent/context.md` holds exactly one accepted plan during execution, or no plan. Recording a plan does not authorize implementation. Project identity, scope, and overall status belong in `docs/project.md`; accepted contracts belong in `AGENTS.md`, a routed reference, code, or configuration; completed execution history belongs in Git.

Current state: of 15 sections, only `custom-section` accepts `@theme`; `footer` uses section blocks; `product` accepts `@app` only; the other 12 have no blocks. If sections compose theme blocks directly, the Container (`sections/custom-section.liquid`) loses its purpose; the user is considering deleting it (2026-09-22). No `templates/*.json` or `config/settings_data.json` currently places it.

## Settled here, not yet migrated

- **The Batch SOP stays in `AGENTS.md` (A, user 2026-09-22).** Workflows are the most effective content in an agent entry file and belong in it, because the entry file is always read while referenced docs are read about 90% of the time (Augment Code study). The same study puts the best length at 100–150 lines (now 163) and finds that 30+ prohibition-only rules hurt. Claude Code guidance: the entry file is advisory; rules that must always hold become hooks or lint. A later trim toward 150 lines is optional. Sources: https://www.augmentcode.com/blog/how-to-write-good-agents-dot-md-files, https://code.claude.com/docs/en/best-practices.
