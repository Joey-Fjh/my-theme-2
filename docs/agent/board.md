Facts (Shopify docs "Blocks" and "Theme blocks quick start", via Shopify Dev MCP): any section whose schema accepts `@theme` (or names block types) can use theme blocks; section blocks work only in their own section, cannot nest, and cannot be mixed with theme blocks in one section; AI-generated blocks need sections that accept `@theme`. Official Skeleton ships only `custom-section` with `group` and `text` as a minimal example; this repository added `heading` and `button`. Current state: of 15 sections, only `custom-section` accepts `@theme`; `footer` uses section blocks; `product` accepts `@app` only; the other 12 have no blocks. Open questions: which sections become block-composed and which stay fixed (for example, cart line items, search results grid, password form); migrating `footer` section blocks and product parts to theme blocks; merchant data in `templates/*.json` and `sections/*-group.json` would need migration and separate authorization; `docs/project.md` allows Horizon as the organization reference, so this is organization, not new inventory. If sections compose theme blocks directly, the Container (`sections/custom-section.liquid`) loses its purpose; the user is considering deleting it (2026-09-22). No `templates/*.json` or `config/settings_data.json` currently places it.

## Settled here, not yet migrated

- **The Batch SOP stays in `AGENTS.md` (A, user 2026-09-22).** Workflows are the most effective content in an agent entry file and belong in it, because the entry file is always read while referenced docs are read about 90% of the time (Augment Code study). The same study puts the best length at 100–150 lines (now 163) and finds that 30+ prohibition-only rules hurt. Claude Code guidance: the entry file is advisory; rules that must always hold become hooks or lint. A later trim toward 150 lines is optional. Sources: https://www.augmentcode.com/blog/how-to-write-good-agents-dot-md-files, https://code.claude.com/docs/en/best-practices.
